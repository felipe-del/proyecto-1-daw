- imagen_configuracion BYTEA.

Prueba JPEG real:

- Firma JPEG comprobada: FF-D8-FF.
- Cierre JPEG comprobado: FF-D9.
- Flujo probado: JPEG real -> Base64 -> JSON -> controller -> Buffer -> BYTEA -> consulta -> Base64.
- Comparación byte a byte: correcta para motor, carro, especificación y configuración.
- Actualización de imagen: probada en las cuatro tablas.
- Registro temporal eliminado.

Frontend de imágenes:

- Los cuatro formularios usan input type=file.
- Los cuatro inputs usan accept=image/jpeg.
- Los dos JavaScript usan FileReader y readAsDataURL.
- El JSON transporta la imagen Base64.
- Los listados y consultas reconstruyen data:image/jpeg;base64,... dentro de img.
- No se usa multer, multipart/form-data, axios ni librerías de imágenes.

Eager:

- GET /postgres/carros-eager: INNER JOIN carros_carrera y motores_carrera, con datos de ambas tablas.
- GET /postgres/configuraciones-eager: INNER JOIN configuraciones_carro y especificaciones_motor, con datos de ambas tablas.
- Ambas consultas usan pool.query y mantienen el comentario CARGA EAGER.

CRUD final:

- FK válida probada.
- FK inválida rechazada por PostgreSQL con respuesta 500, conservando el patrón de semana 4.
